================================================================
  9/5 驗收 Demo 小抄
  指令直接複製貼上・「說」的部分照唸即可
================================================================


【 開場前的準備 】

 瀏覽器開三個分頁：
   分頁1  http://52.199.107.190
   分頁2  http://nkc202-cicd-alb-1176135322.ap-northeast-1.elb.amazonaws.com
   分頁3  https://github.com/CarlosChangYao/aws-cicd-pipeline/actions

 打開終端機，貼這行：

cd ~/Desktop/Tibame/專題 && git pull -q && echo 準備好了


================================================================
  第 1 步：看現在的網站
================================================================

 動作：切到「分頁1」，按重新整理

 說：
   「這是我的網站，現在正在 AWS 上跑。
     請大家記一下這個版本號。」


================================================================
  第 2 步：改一行程式碼
================================================================

 貼這行：

sed -i '' "s|（[^）]*）</h1>|（$(date '+%m月%d日')現場 Demo）</h1>|" app/app.py && sed -n '31p' app/app.py

 說：
   「我現在改網頁標題這一行，把它改成今天的日期。」


================================================================
  第 3 步：送出（唯一的人工動作）
================================================================

 貼這行：

git add -A && git commit -m "現場 Demo" && git push origin main

 說：
   「我按下送出。這是我今天唯一會做的動作，
     接下來我不會再碰任何東西。」


================================================================
  第 4 步：看機器自己跑（等 80 秒）
================================================================

 動作：切到「分頁3」，看四個階段依序變綠

 說：
   「機器現在自己在做四件事：
     第一，跑測試——測試不過的話後面完全不會執行。
     第二，把程式打包成映像檔，上傳到 AWS 的倉庫。
     第三跟第四，同時部署到兩台不同的機器。」

 【 等待時的補充話術，挑一兩句講就好 】

   「版本號是機器自己編的，我沒有機會填錯。」

   「整個過程沒有用到任何 AWS 密碼。
     GitHub 是跟 AWS 換一張一小時就過期的臨時通行證。」

   「部署也不是用 SSH 連進去的。
     那台機器連 22 port 都沒開，我把 SSH 服務整個關掉了。」


================================================================
  第 5 步：回去看網站，它自己變了
================================================================

 動作：切到「分頁1」，按重新整理

 說：
   「標題變成今天的日期了，版本號也跳號了。
     我從按下送出之後，什麼都沒做。」

 貼這行（對照用）：

git log --oneline -1

 說：
   「網頁上顯示的編號，跟我電腦裡的完全一樣。
     所以線上跑的到底是哪一版程式碼，是百分之百確定的。
     這在金融業叫『可追溯性』，稽核一定會問。」


================================================================
  收尾（老師若問，或時間夠再講）
================================================================

 說：
   「我報告裡有記錄：一開始純手動部署，要 18 個步驟、16 分鐘，
     還失敗了兩次。現在是 1 個步驟、80 秒、零失敗。」


================================================================
  萬一出狀況
================================================================

 網站打不開      → 改用分頁2（那是另一台獨立的機器）
 Actions 卡住    → 頁面上按「Re-run all jobs」
 push 被拒絕     → 先貼：git pull --rebase
                    再貼：git push origin main
 完全跑不動      → 翻報告第三章，數據和截圖都在
