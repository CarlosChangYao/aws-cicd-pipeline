##############  Demo 正片（約 4 分鐘）  ##############


================================================================
  第 1 步：先說故事（20 秒，不要跳過）
================================================================

 動作：切到「分頁1」，重新整理

 說：
   「在開始之前，我先設一個情境。

     假設今天主管機關發函，要求所有投資相關頁面
     都必須加上一行風險警語，而且要盡快上線。

     這是券商很常遇到的狀況——
     程式只要改一行，但傳統流程要：
     開變更單、跑簽核、排收盤後的上線窗口、
     通知 IT 值班、通知業務單位待命。
     最快也是隔天。

     我現在用我這條流水線做一次給大家看。

     先記一下現在的版本號，還有——現在畫面上沒有警語。」


================================================================
  第 2 步：改程式（貼一行）
================================================================

 貼：

bash 現場改一行.sh

 畫面會印出剛剛加的那一行，指著它說：

 說：
   「就這一行。加了一個風險警語的區塊。」


================================================================
  第 3 步：送出（今天唯一的人工動作）
================================================================

 貼：

git add -A && git commit -m "依主管機關要求加註風險警語" && git push origin main

 說：
   「我按下送出。
     接下來到警語上線為止，我不會再碰任何東西。」


================================================================
  第 4 步：切到分頁2，看機器自己跑
================================================================

 動作：切到「分頁2」(GitHub Actions)，看四個階段依序變綠

 說：
   「機器現在自己在做四件事：
     第一，跑測試——測試不過的話，後面三個完全不會執行。
     第二，把程式打包成映像檔，推到 AWS 的倉庫。
     第三跟第四，同時部署到兩台不同的機器。」


================================================================
  第 5 步：★ 切到分頁3，看 AWS 上自己長出新版本
================================================================
  這是老師要看的「開 AWS」。等待的時間都花在這裡。

 動作：切到「分頁3」(ECR)，一直按重新整理

 大約 60 秒後畫面會變：

     Images (n)  -->  Images (n+1)      數字自己加一
     最上面多出一列，時間是今天，標籤是剛才那次 commit 的編號

 說：
   「這是 AWS 上的映像檔倉庫。
     大家注意——我從按下送出到現在，完全沒有碰 AWS。
     這個新版本是流水線自己推上來的。」

 指著最上面那一列的三個標籤：

   「一個映像檔掛了三個標籤。
     latest 是最新的，但下一次建置就會被搶走；
     中間是版本號，給人看的；
     最後這一串是 commit 編號，永遠不會被蓋掉。
     所以我要退回舊版，就是指定這一串。」


================================================================
  第 6 步：回分頁1，收尾（最重要的一段）
================================================================

 動作：切到「分頁1」，按重新整理  → 警語出現了

 說：
   「警語上線了。版本號也跳號了。」

 貼（對照用）：

git log --oneline -1

 說：
   「網頁上顯示的 commit 編號，跟我電腦裡的完全一樣。
     所以線上到底跑的是哪一版程式碼，是百分之百確定的。
     這在金融業叫可追溯性，稽核一定會問。」

 ★★ 最後這段是整場的結論，慢慢講 ★★

   「回到一開始的情境。

     用傳統流程，這行警語要等到隔天才會在客戶眼前出現，
     而且要動員五個人、佔掉一個下午。

     剛才這一次，從我按下送出到上線，不到兩分鐘，一個人。
     而且是盤中就能做，因為換版的時候服務不會中斷。

     對券商來說，這不只是快，
     是把作業風險跟法遵回應時間一起壓下來。」



##############  被問到才開的三頁  ##############


 ---- 問「怎麼做到不斷線」 → 開 ECS ----

 https://ap-northeast-1.console.aws.amazon.com/ecs/v2/clusters/nkc202-cicd-cluster/services/nkc202-cicd-service/health?region=ap-northeast-1

 指著：  Tasks (2 Desired)   2 running | 0 pending

 說：
   「這裡同時跑著兩份我的程式。
     換版時先把新的開起來、確認健康了，才關掉舊的。
     中間永遠有人在服務，所以不會斷。
     我實測過部署期間打 300 次請求，300 次全部成功。」


 ---- 問「安全怎麼做」 → 開 EC2 ----   ★ 這頁最強

 https://ap-northeast-1.console.aws.amazon.com/ec2/home?region=ap-northeast-1#InstanceDetails:instanceId=i-0937ad0e32c5fedca

 動作：點中間的「Security」頁籤，往下捲到 Inbound rules
 畫面上只有一條：  Port 80 / TCP

 說：
   「這台機器的防火牆只有一條規則，80 port，也就是網頁。
     沒有 22，代表誰都不能 SSH 連進來——包括我自己。
     我也沒有建任何金鑰。

     那怎麼部署？靠 AWS 的 Systems Manager，
     是機器主動向外拿指令，不是外面連進來，所以門不用開。

     金鑰外流和特權帳號被盜用，是金融業稽核最常問的兩件事。
     這個做法讓這兩個風險根本不存在——
     不是把鑰匙管好，是根本沒有鑰匙。」


 ---- 問「環境怎麼建的」 → 開 CloudFormation ----

 https://ap-northeast-1.console.aws.amazon.com/cloudformation/home?region=ap-northeast-1#/stacks

 畫面上：兩個堆疊，都是綠色 CREATE_COMPLETE

   nkc202-cicd-base  = 地基（VPC、子網路、防火牆、EC2、IAM）19 個資源
   nkc202-cicd-ecs   = 上層（負載平衡器、ECS、任務定義）  12 個資源

 說：
   「這兩個檔案總共建了 31 個資源。
     我沒有在 console 上一個一個點，我寫了兩個 YAML 交給 AWS。
     這叫基礎設施即程式碼。

     我刻意拆成兩個：地基幾乎不會動，動了就是大事；上層常常要調。
     分開之後改上層完全碰不到地基，爆炸半徑小。

     而且檔案在 GitHub 上，誰改過哪一行都查得到。
     對金融業來說這就是變更管理。」


 ---- 問「這樣要花多少錢」 ----

 說：
   「開發階段幾乎都在免費額度內。
     目前主要成本是負載平衡器和 Fargate，一天大約 1.3 美元。
     我有設預算告警，驗收後會把資源全部清掉。」


 ---- 問「為什麼沒做關 5（跨雲）」 ----

 說：
   「我評估過。要另外開 GCP 帳號、重做一套部署，
     大概五到八小時，但 Tier 不會因此提高。
     我把時間放在把關 4 的零停機實測做扎實。
     評估過程寫在報告裡。」
